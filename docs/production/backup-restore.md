On 2026-10-03 the operator selected Neon Free plus external automated encrypted backups instead of upgrading Neon for managed scheduled snapshots. Console evidence shows the production project's history window is set to its current 6-hour maximum; no snapshot schedule is configured. This changes the launch requirement from provider-managed daily backups to externally operated daily backups; it does not waive backup acceptance.

Launch requires daily automated database exports, encryption before upload, durable external storage, restricted backup/restore rights, failure and stale-backup alerts, a documented retention value, independently recoverable decryption keys, and a successful restore from the stored encrypted artifact. A local temporary archive is not sufficient. Neon history recovery complements these exports but does not extend their recovery granularity beyond the export times. External storage and scheduler selection, retention, approved RPO/RTO, alert delivery, and operational ownership remain **BLOCKED**. No paid plan or new external resource has been provisioned by this decision.

Before every production migration, an operator records the latest successful backup and its age. A high-risk migration requires an immediate snapshot. A backup is not accepted merely because a job reported success: at least quarterly, restore it into a new isolated database, run `prisma migrate status`, content validation, row-count/sampling checks, health, Bazi/Liuyao fixed fixtures, and read-only smoke tests. Destroy the drill environment through the provider's audited process after evidence is retained.

Restore evidence records backup identifier, source and isolated destination, timestamps, operator/reviewer, application commit, migration head, RPO achieved, RTO achieved, validation results, and any data loss. Never restore over production as a drill.
